dsh-solidwork · workflow map

把三视图变成 可验证的 SolidWorks 实体

这个项目的核心不是"让模型调用 CAD"，而是把一次建模拆成可复核的证据链： 先读图并锁定尺寸台账 → 出计划并取得批准 → 用一次完整的 Feature Graph 构建 → 用客观测量（投影、剖视、体积、质量属性）验证 → 才允许说"完成"。 模型全程看不到 COM / Shell / 宏 / 脚本，只有 12 个高层工具。

01分层架构

自上而下六层，每一层只依赖下一层的契约。模型能改的只有最上面一层。

Client
DSH web / --profile solidworks 浏览器会话preset: solidworks-cad
选择 preset 决定 CAD 指令与技能；profile 额外挂载 policy 插件。
Boundary
宿主侧 MCP client · 12 个高层工具
由宿主进程拥有，不随会话/preset 代际变化；工具返回紧凑单行 JSON 信封。
Instruction
solidworks-cad skill + references
SKILL.md（≤550 行）+ 5 份参考文档，通过 read_mcp_resource 分页读取。
Orchestration
Python 编排层 · 作业策略 · 事务 · 备份 · 确认
orchestrator.py / policy.py / job_store.py：job_token 鉴权、白名单编辑、undo 事务、写前备份。
Compiler
SolidPilot 确定性编译器 + C# 执行服务
Feature Graph IR → 节点日志 → 低层 CAD 调用。编译器内没有 LLM，可复现。
CAD
SolidWorks COM
真正的几何内核。只被 C# 执行服务触碰。
Denied
模型不可达：COM / Shell / 宏 / 脚本 / REST / 桌面自动化 / 旧低层 MCP
无回退路径。表达不了的操作必须报 CAPABILITY_GAP，工具面缺失报 MCP_UNAVAILABLE。

02主工作流

任何 CAD 任务的固定骨架。带琥珀色编号的是门：不通过就不许写模型。

读状态inspect_state · scope=state

确认 SolidWorks 就绪、当前活动文档、是否有被锁定的文档。此步不需要凭据。

按需读参考inspect_state · scope=reference

只读这次任务需要的 topic：contract、mapping_part、verification、feature_graph_quickref… 大文档分页返回，用 reference_offset 续读，不要重复同一个调用。

（仅图纸/图片任务）完成有界识读

见 §3 图纸识读。产出：尺寸台账 + 问题清单，交给用户确认。

出计划并取得批准PLAN.md · inline

计划写在回复里（本 preset 没有文件工具），≤70 行 / ≤4 KB，用 todo_write 跟踪进度。 任何拓扑、方向、尺寸、特征顺序的变化都会产生新版本，必须重新批准。

开作业start_job

拿到 job_id + 私密 job_token，并锁定目标文档身份。之后每次深层检查与写操作都要带这对凭据。 用户中途切换文档 → 作业目标失效，下一次写入被拦截。

建模submit_feature_graph

新模型优先用一次完整的 submit_feature_graph(fresh_document=true)；不为了"造检查点"而把一张图拆开。 大而复杂的不对称件按里程碑推进（见 §5）。

看响应 + 看客观状态inspect_state

不信返回码，信测量：特征树、几何、体积、质量属性、面/边索引。拓扑一变，旧索引立刻作废，必须重新读。

逐视图/剖视校验

主视图、俯视图、左视图、每一个给出的剖视图都要对得上。对不上就进 L5 回环，而不是"看起来差不多"。

产出与收尾save_or_export · finish_job

保存/导出受策略约束（指定路径的保存必须确认）。finish_job 跑最终客观验证并关闭作业——写操作流程中它是强制的。

最终报告

文档与产物、实际完成的操作、做过的客观验证、status / verification_status / recovery_status / trust_level、 假设与不可用检查。绝不凭外观或返回码宣称成功。

03图纸识读（intake）

整张图纸塞进模型视野时，小尺寸文字只剩几个像素——"猜尺寸"正是这套流程要消灭的失败模式。 识读是只读的，不碰 CAD、不需要 job，因此发生在 start_job 之前。

三轮读取，然后必须收敛

  • Round 0 — 一次 OCR：read_drawing_text 用 Windows 内置引擎整张扫描，约 3 秒，不计入裁剪预算。 结果当作候选表：确定性高但小符号会错读。
  • Round 1 — 一次总览：read_drawing_region 空 region，返回带网格的整图，免费。 记下每个视图、投影制式、比例、标题栏，以及完整的待读尺寸簇清单（单元格 C4 或像素框）。
  • Round 2 — 一次调用读完所有簇：regions=["B2","C4",…]，一次最多 12 个，共用一个 zoom。 一次调用，而不是每个簇一次。
  • Round 3 — 至多再一次：只为仍然看不清的值，用更紧的框或更高 zoom。

硬约束

  • 每步 45–90 秒，所以步数和裁剪数一样重要：批量才是重点。
  • 预算 15 次裁剪 / 张图（总览免费）。INTAKE_BUDGET_EXHAUSTED = 现在就把识读结果发出去。
  • 同一框重复读被工具拒绝：REGION_ALREADY_READ（按图片 SHA-256 记忆）。
  • reset_budget=true 只能在用户明确要求继续读之后使用。
  • 禁止：量像素、开浏览器、跑脚本、用别的工具估尺寸。图纸没写的值就是 UNKNOWN，要问，不要算。

识读结果 = 台账 + 问题清单

尺寸台账字段：id、数值、类型、所属视图、单元格/框、是否清晰可读。 连同问题清单一并通过 ask_user_question 发给用户；候选读数可以提（"看着像 26，确认？"）， 但在用户回答前绝不进入台账成为事实。用户回答之前不许再放大、不许出 PLAN.md、不许出 Feature Graph。

证据优先级：显式标注尺寸 > 剖视图（材料/空腔/内部过渡）> 轴测图（拓扑、特征存在性、左右手、前后关系，不给真实尺寸） > 正交视图交叉核对 > 像素测量与视觉比例（最低，永不覆盖显式值）。冲突要记录并采用最高级证据。

05Feature Graph 流水线

模型产出的是特征意图（IR），不是一串工具调用。编译器确定性地把它降级成 SolidWorks 操作，再逐节点验证。

里程碑策略（不对称铸件 / 交叉孔阀体 / 支架类）

  • 超大图会在中途失败，而恢复结果可能是被悄悄简化的零件——所以拆成有序里程碑，而不是一张巨图。
  • 按形状顺序推进：最不对称的真实轮廓 → 法向边界面 → 内部孔槽 → 斜面 → 曲面/回转特征。
  • 每个里程碑之后，只校验约束它的那些视图，再规划下一个。
  • 有证据的每个特征都必须落在某个里程碑里；为了塞进一张图而丢特征属于计划缺陷，不是简化。
  • 草图尽量简单并完全约束：先几何关系，再位置尺寸，再形状尺寸；首个基准/草图尽量锚到原点。

06事务、失败与信任

写操作永远在 undo 事务里；已有文件尽量做首次写入备份。备份是恢复证据，不是"文档已还原"的证明。

响应状态处理

status动作
completed核对 verification、partial_state、completed_steps 后才继续
pending_confirmation进入确认流程并暂停
failed停止，检查 error 与 recovery_status
partial停止；部分状态可能残留，报告步骤/备份/恢复结果
verification_failed停止；已执行但客观验证未通过

信任等级

trust_level含义
unverified未验证，不能宣称完成
built_unverified已构建，关键客观证据不可用
drawing_consistent工程图方向证据一致，但无参考实体比较
verified最终客观验证通过

确认协议（一次性令牌）

暂停并请求request_confirmation

用同一 job 与 action ID 请求；原样展示返回的 action_summary。原始请求不构成危险动作的批准。

等一条新的明确批准消息

MCP 无法在密码学上证明批准来自人类；preset 与 skill 要求必须是一条全新的用户消息。

执行confirm_action

只接受未变化的 action、token、确认文本与摘要。令牌不可复用；风险或摘要一变就必须重新确认。

操作限制

文档身份
用户切换文档会使作业目标失效，并拦下下一次写入。
只读锁定
对非本作业拥有的文档写入会返回 JOB_DOCUMENT_READ_ONLY。
回滚边界
跨文档与外部文件动作仍超出恢复能力；rollback_failed 必须人工复核。

07工具边界

调用前缀 mcp__solidworks__。没有低层回退路径。

工具风险用途
start_job读/打开连接 SolidWorks，按需打开文件，锁定活动文档并返回 job_id + job_token
inspect_state只读就绪状态、文档分析（特征/几何/质量属性/面/边/选择集）、受控 recipe/schema 参考
submit_feature_graph写/批量用确定性编译器执行一张完整的 Feature Graph
apply_document_edits写/破坏性/批量对已锁定文档执行白名单参数化编辑
drawing_workflow写生成生产工程图：视图、剖视、局部、标注、BOM/孔表、标准检查
save_or_export写/输出保存、导出、批量导出、关闭（受安全策略约束）
request_confirmation控制轮换一次性令牌，返回用户必须原样批准的摘要
confirm_action控制在新批准之后执行恰好一个动作
cancel_action控制取消排队中的确认动作（用于释放待定 Feature Graph）
finish_job验证跑最终客观验证并关闭作业；写流程中强制
read_drawing_text只读整张图纸 OCR：每个文本 + 位置 + 网格单元，识读第 0 轮
read_drawing_region只读按网格单元或像素框放大读小尺寸；无需 job，不碰 CAD

放行的支撑工具（同一策略插件）

ask_user_question todo_write skill modlens_read_image list_mcp_resources read_mcp_resource

图片只接受本地路径；http://、https://、ftp://、file:// 一律拒绝。 本 preset 没有文件工具，所以技能参考只能通过 read_mcp_resource（solidworks://skill/references/<file>.md）读取； 带 .. 的 URI 报 SKILL_RESOURCE_TRAVERSAL_REFUSED，不在清单内的名字报 SKILL_RESOURCE_NOT_FOUND。

编辑白名单（apply_document_edits）

modify_dimensionedit_feature set_part_materialadd_edge_feature create_patternadd_reference_geometry add_sketch_constraintinsert_toolbox_component create_exploded_view

用当前特征名与刚读到的几何引用；拓扑一变必须重新检查。删除与大批量编辑进入确认流程。

编排器内部低层命令（begin_undo_scope、rollback_undo_scope、export_document 等） 不是模型接口。模型需要的能力必须由 12 个高层工具表达出来，否则报 CAPABILITY_GAP。
