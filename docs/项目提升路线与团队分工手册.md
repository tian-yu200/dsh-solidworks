# SolidWorks AI 建模项目：下一步计划和社团分工说明

这份说明是给社长看的分工单。项目的核心功能（让 AI 看工程图纸，自动控制 SolidWorks 建出三维零件）我自己已经搭得差不多了，但外围还有不少资料整理、小工具和文档的杂活，一个人忙不过来，想请社长帮忙分给 2 到 3 个同学一起做。

下面拆出来的活都特意挑了简单、独立的部分。负责的同学**不需要在自己电脑上装 SolidWorks**，也不需要看懂整个项目的代码，平时用 DeepSeek 或者 Claude 免费版就能做完。

## 现在做到哪了，接下来要补什么

目前这套程序在常见的简单机械零件上，大部分已经能照着图纸自动建出来。但真想拿出去给工厂或者代画接单用，还有几个明显短板：

1. 图纸上写的中文材料（比如 45 钢、HT200、Q235A），SolidWorks 英文材料库认不出来，建完没法直接算重量报价。
2. 现在只能把图纸当照片看，AI 偶尔会看错数字或漏看切边；其实很多工厂发的是 CAD 电子图（DXF 格式），直接读文件里的数字和圆孔会准得多。
3. 之前一直在拿比赛题测试，还没真接过工厂或闲鱼上的真实单子，需要把接单表格、沟通话术和安装说明先准备好，方便跑通前几单。
4. 一些更深层的改动（比如让建出来的草图自动带尺寸约束、修 SolidWorks 自动启动慢的问题、把新模块接进主程序）都和核心代码绑得很紧，我来自己做，不交给同学折腾。

## 分工前要提前交代的几条规矩

社长派活时顺口提醒一下大家就行，能省掉后面很多返工：

1. **不要改项目里原有的代码和文件。** 大家只新建自己的文件。会用 Git 的同学拉一个新分支提交；不会用 Git 的同学，直接把做好的表格、文档或者 `.py` 文件打包发我微信或 QQ，我统一测试后再合进项目。
2. **机械数据别让免费 AI 瞎编。** DeepSeek 和 Claude 免费版遇到不确定的密度或国标尺寸，经常会顺口编一个看起来很像的数字。拿不准的条目直接留空写个 `待核对`，千万别硬凑。
3. **对外写的文案和表格守住三条底线。** 一是不接大学生机械制图作业和毕业设计代做；二是没实际测过的数据不乱写（比如别吹“效率提高 3 倍”，也别写“数据绝对不出本地”）；三是绝不提破解版 SolidWorks 或任何绕过正版检测的内容。具体原因都写在 `docs/产品演进与商业化落地指南.md` 里。

## 三个人的具体任务

### 1 号同学：整理中文材料对照表和标准孔表

平时图纸上写 45 钢、HT200、Q235A、40Cr、ZL105 这些牌号，SolidWorks 默认英文库搜不到，每次都提示找不到材料，导致没法直接算出零件有多重、料钱多少。这块活就是要做一张靠谱的对照表。

具体要做三件事（第 1 件必做，后两件按时间尽力做）：

1. **做一份常用机械材料对照表**（存成 `mcp-server-solidworks-main/compiler/solidworks/pycompiler/gb_materials.json`，不会写 JSON 就先做 Excel 表格发我，我来转）。
   - 覆盖 40 种左右工厂常见材料，包括：45 钢、Q235（Q235A/B）、20 钢、40Cr、42CrMo、HT150/200/250/300、QT450-10/500-7、ZG230-450、304/316L 不锈钢、6061/6063/7075/2017 铝合金、ZL102/104/105 铸铝、ADC12、H59/H62 黄铜、ABS、POM、尼龙 PA6、PC、PTFE。
   - 每种材料写清楚这几项：标准中文名、图纸常见别名（比如 `45`、`45#`、`45号钢`）、密度（单位 `g/cm³`，标明出处）、SolidWorks 英文材料库里对应的名称（比如 45 钢对应 `AISI 1045 Steel, cold drawn`，实在没有精确对应的再写密度接近的备选并备注清楚）。
2. **写一个简单的材料查询小脚本（可选，会点 Python 再做）**，文件放在同目录的 `gb_materials.py` 和 `tests/test_gb_materials.py`。功能很简单：输入 `"45钢(调质)"` 或 `"  ht 200 "`，先去掉多余空格和括号，再查出对应材料；查不到直接返回 `None`，不要乱猜；顺便写个小函数，输入体积（立方厘米）和材料名能算出大概多少公斤。
3. **整理一张常用沉头孔尺寸表（可选）**，按国标 GB/T 152.2 和 GB/T 5277，列出 M3 到 M16 沉头孔对应的通孔径、沉孔径和沉孔深度，存到 `tools/quote_calc/gb_counterbore_table.json` 或 Excel 表格里。

数据格式示例：

```json
{
  "canonical_gb": "45钢",
  "aliases": ["45", "45#", "45号钢", "S45C", "C45"],
  "category": "carbon_steel",
  "density_g_cm3": 7.85,
  "density_source": "GB/T 699 常用工程密度",
  "sw_candidates": [
    {"library": "SolidWorks Materials", "name": "AISI 1045 Steel, cold drawn", "match_kind": "equivalent"},
    {"library": "SolidWorks Materials", "name": "Plain Carbon Steel", "match_kind": "density_fallback"}
  ],
  "note": "默认英文库没有45钢时，先用 AISI 1045 替代并在交付说明里写明"
}
```

直接发给 DeepSeek 或 Claude 免费版的指令：

> 帮我整理一份中国机械加工最常用的 40 种材料对照表，输出 JSON 数组。必须包含：45钢、Q235A、20钢、40Cr、42CrMo、HT150、HT200、HT250、HT300、QT450-10、ZG230-450、304、316L、6061、6063、7075、2017、ZL102、ZL105、ADC12、H62、ABS、POM、PA6、PC、PTFE 等。每条严格按下面字段写：canonical_gb、aliases、category、density_g_cm3、density_source、sw_candidates（写 SolidWorks 默认英文材料库里对应的名称）、note。密度必须查准，如果你对某个材料在 SolidWorks 里的英文名不确定，就在 note 里标明“待核对”，不要自己编名字。

交货标准：表格或 JSON 格式合法，人工抽查一遍密度没有离谱数字；如果写了 Python 脚本，保证运行 `pytest` 全部通过。

### 2 号同学：写一个从 DXF 图纸里读文字和圆孔的小工具

现在程序看图靠的是截图，偶尔会认错小数点或漏看外形。工厂里很多图纸是 CAD 导出的 `.dxf` 文件，里面直接存着精确的标注文字、圆心和直径。我们需要一个独立的小工具，把这些信息从 DXF 里干净地读出来，输出成 JSON，后面我自己来把它接进主程序。

具体要做两件事（第 1 件必做，第 2 件有空再做）：

1. **写 DXF 信息读取脚本**，新建两个文件：
   - `mcp-server-solidworks-main/adapters/dsh/dxf_extractor.py`
   - `mcp-server-solidworks-main/adapters/dsh/tests/test_dxf_extractor.py`
   - 用 Python 的 `ezdxf` 库写一个函数 `extract_dxf_facts(dxf_path, max_entities=5000)`，把 DXF 文件里的数据统一换算成毫米，返回下面这种结构：
     ```json
     {
       "status": "ok",
       "source_path": "...",
       "insunits": "millimeters",
       "unit_scale_to_mm": 1.0,
       "layers": ["0", "DIM", "OUTLINE"],
       "bbox_mm": {"min_x": 0.0, "min_y": 0.0, "max_x": 120.0, "max_y": 80.0, "width": 120.0, "height": 80.0},
       "dimensions": [
         {"entity_type": "DIMENSION", "layer": "DIM", "text": "Ø12", "actual_measurement_mm": 12.0, "pos_mm": [30.0, 40.0]}
       ],
       "texts": [
         {"entity_type": "MTEXT", "layer": "TEXT", "text": "4×Ø6 均布", "pos_mm": [10.0, 75.0]}
       ],
       "geometry_summary": {
         "circles": [{"layer": "OUTLINE", "center_mm": [30.0, 40.0], "diameter_mm": 12.0}],
         "arcs": [{"layer": "OUTLINE", "center_mm": [0.0, 0.0], "radius_mm": 25.0, "start_deg": 0.0, "end_deg": 180.0}],
         "closed_polylines": [{"layer": "OUTLINE", "vertex_count": 4, "bbox_mm": [0.0, 0.0, 120.0, 80.0], "points_mm": [[0,0],[120,0],[120,80],[0,80]]}],
         "line_count": 24,
         "truncated": false
       },
       "warnings": []
     }
     ```
   - 几个细节要处理好：CAD 里的特殊符号要转成正常字符（`%%c` 转 `Ø`，`%%d` 转 `°`，`%%p` 转 `±`，去掉 MTEXT 里的字体格式代码）；遇到英寸单位要乘 `25.4`，没设单位就按毫米算并记一条 warning；如果传进来的文件不存在或者损坏了，返回 `{"status": "error", "error_code": "...", "message": "..."}`，不要直接报错崩溃；图元超过 5000 个时截断并把 `truncated` 标成 `true`。
   - 测试脚本里直接用 `ezdxf.new()` 现场生成 4 到 5 张简单测试图（多孔方板、同心圆法兰、带中文和 `%%c` 符号的图、英寸图、损坏文件），测一遍确认都能正常读出，数字误差小于 `0.001 mm`。
2. **顺手测一下电子版 PDF 能不能抽文字（可选）**，新建 `mcp-server-solidworks-main/adapters/dsh/pdf_vector_probe.py` 和对应测试。用项目里已经装的 `pypdfium2` 读 PDF 里的文字层，判断一份 PDF 是扫描件还是 CAD 直接导出的电子版。

直接发给 DeepSeek 或 Claude 免费版的指令（建议分两次问，第一次让它写主文件，第二次让它写测试，免费版额度更够用）：

> 请帮我写一个独立的 Python 文件 `dxf_extractor.py`，用 `ezdxf` 读取 DXF 工程图纸。提供一个函数 `extract_dxf_facts(dxf_path: str, max_entities: int = 5000) -> dict`。要求：1. 自动读取 `$INSUNITS` 换算成毫米（英寸乘 25.4，米乘 1000，未设置默认按毫米并在 warnings 里记录）；2. 提取所有 DIMENSION、TEXT、MTEXT 的文字内容和坐标，把 `%%c`/`%%d`/`%%p` 转成 `Ø`/`°`/`±` 并清理 MTEXT 格式控制符；3. 提取圆（圆心和直径）、圆弧（圆心、半径、起止角）、闭合多段线、直线数量和整体外框范围，常见 INSERT 块展开一层；4. 文件不存在或损坏时捕获异常返回 `{"status": "error", "error_code": "...", "message": "..."}`；5. 超出 `max_entities` 时截断并标 `truncated: true`。返回字段严格按我贴给你的 JSON 模板写。

交货标准：在本机跑通 `pytest mcp-server-solidworks-main/adapters/dsh/tests/test_dxf_extractor.py -v` 全绿，不改项目原有代码。
